## 화면

- **좌우 2단** — 왼쪽 기록, 오른쪽 서면 작성. 각각 따로 스크롤한다. 기록형은
  기록이 1만~9만 자라 위아래로 쌓으면 쓰면서 보기가 불가능하다. 900px 미만에서는 1단.
- **서면별 탭** — 한 회차에 검토보고서·변론요지서처럼 서면이 둘이면 탭으로 나뉘고
  답안도 따로 저장된다.
- **임시저장** — 입력이 멎고 0.6초 뒤 자동 저장. 서면 단위(`{시험ID}::t{번호}`).

답안 전문은 **이 기기에만** 남는다(IndexedDB). 원격에는 점수·시간 같은 요약만 간다.

## 데이터 만들기

원본 hwp/txt는 저작권 자료라 저장소에 없다. 경로를 환경변수로 주고 돌린다.

```bash
set RECORD_RAW=C:\...\모의고사 기출문제, 모범답안
cd pipeline
python -X utf8 build_record_data.py
```

`data/{과목}/index.json` + `exams/*.json`을 다시 만든다.

### 작성할 서면을 어떻게 찾는가

과제 표기가 과목마다 근본적으로 다르다.

| 과목 | 표기 | 예 |
|---|---|---|
| 공법 | 로마자 번호 + 배점 | `Ⅰ. 헌법소원심판청구서의 작성 (50점)` |
| 형사법 | 문장 안, 번호·배점 없음 | "…검토보고서를, …변론요지서를 각 작성하되" |
| 민사법 | 과제 하나, 번호·배점 없음 | "…소장을 작성하시오." |

번호나 배점으로 찾으면 공법만 잡히고 나머지는 전부 실패한다. 그래서 번호가 아니라
**작성할 서면 종류**(소장·답변서·변론요지서·검토보고서·헌법소원심판청구서 등)를
기준으로 찾는다. 배점은 서면 이름 뒤에 붙어 있으면 같이 읽고, 없으면 비워 둔다.

각 회차의 `taskSource`가 무엇을 보고 뽑았는지 남긴다.

| `taskSource` | 뜻 | 건수 |
|---|---|--:|
| `points` | 배점까지 찾음 | 36 |
| `document` | 서면 종류만 찾음(배점 없음) | 124 |
| `none` | 못 찾음 — 답안칸 하나로 폴백 | 5 |

`none` 5건(공법 2014-3차·2015-1차, 민사법 변시 3회, 형사법 2014-3차·2016-2차)은
문제 표지 형식이 달라 자동으로 못 뽑았다. 앱은 답안칸 하나를 주고 "기록에서
확인하세요"라고 알린다 — **틀린 과제 목록을 지어내지 않는 쪽**을 택했다.

## 채점 근거 — 해설서 결합

변시 15회분은 채점기준표가 공개되지 않는다. 그 공백을 **기록형 해설서**로 메웠다.

| 과목 | 회차 | 채점기준표 | 해설 | 근거 있음 |
|---|--:|--:|--:|--:|
| 공법 | 55 | 40 | 15 | 55 |
| 민사법 | 55 | 40 | 15 | 55 |
| 형사법 | 55 | 40 | 14 | 54 |
| **합계** | **165** | **120** | **44** | **164** |

근거가 없는 건 형사법 변시 15회 한 건뿐이다(가장 최근 회차라 해설서가 아직 없다).

### 쓴 책과 판정

| 책 | 쪽수 | 회차 머리글 | 결과 |
|---|--:|--:|---|
| 김유향 공기록 해설(공법) | 364 | 44% | 15회차 결합 |
| 노수환 핵심형사기록(형사법) | 819 | 48% | 14회차 결합 |
| 정연석 로스쿨 기록형 기출문제집(3과목) | 1,032 | 45% | 15회차 결합 |
| 정연석 15변시 기록형 해설 | 21 | 100% | 1회차 결합 |
| 김기용 COMPACT 형사기록 | 396 | 17% | **회차 매칭 안 함** |

김기용 책은 창작 기록 위주라 회차별로 나뉘지 않는다. 무리하게 붙이면 엉뚱한
해설이 달리므로 제외했다 — 쟁점 태깅용 참고자료로는 여전히 쓸 수 있다.

### 어떻게 회차를 찾는가

사례집 목차를 파싱하는 사례형 방식은 여기서 통하지 않았다. 다섯 권의 편집이
제각각이고, 김유향 책은 OCR본이라 목차 자체가 깨져 있다("재 2 편", "71 줄문제집").

대신 **쪽마다 반복되는 회차 머리글**("2023년 제12회 변호사시험")로 나눈다.
OCR이 글자를 흘려도 숫자와 '회/년'은 대체로 살아남는다. 머리글이 없는 쪽은
직전 회차를 물려받는다.

### 붙인 뒤 반드시 대조한다

머리글이 잡혔다고 내용까지 맞다는 보장은 없다. 그래서 **문제에만 나오는
고유명사**(기록형은 당사자 이름이 회차마다 다르다)를 뽑아 해설에 실제로
등장하는지 센다. 적중률 50% 미만은 붙이지 않는다.

이 대조로 실제 오매칭을 걸러냈다. 공법 2016-2차에 붙었던 11쪽은 적중률이
25%였는데, 열어 보니 문제는 건축·용도변경허가 사건인데 해설은 재외동포법·
환경영향평가법이었다 — 회차별 해설이 아니라 유형별 청구취지 예시를 모아 둔
정리 페이지가 회차 하나로 잡힌 것이었다. 쪽수만으로는 걸러지지 않았다.

최종 결합 45건은 전부 적중률 0.5 이상이다.

### 재생성

```bash
set RECORD_PDF=C:\...\모의고사 기출문제, 모범답안
cd pipeline
python -X utf8 extract_casebooks.py   # PDF → 쪽별 txt (2,632쪽, 20분쯤)
```

## 쟁점 태깅 — 해설과 채점기준표에서 뽑는다

기록 전문은 회차당 1.5~9만 자인데 대부분이 진술조서·판결문 같은 **사실관계**다.
쟁점은 거기 적혀 있지 않다. 대신 두 곳을 본다.

- **해설**(변시 44회차) — "표현의 자유(과잉금지·명확성), 원고적격, 제소기간"처럼
  쟁점을 이미 정리해 놓았다. 중앙값 37,239자.
- **채점기준표**(모의 120회차) — 배점 항목마다 법리를 적어 둔다. 중앙값 8,908자.

| 과목 | 쟁점 있는 회차 | 쟁점 종수 | 해설 회차 평균 | 기준표 회차 평균 |
|---|--:|--:|--:|--:|
| 공법 | 50/55 | 117 | 20.1 | 8.4 |
| 민사법 | 55/55 | 107 | 17.9 | 8.9 |
| 형사법 | 54/55 | 103 | 14.0 | 8.8 |
| **합계** | **159/165 (96%)** | | | |

해설 쪽이 회차당 두 배쯤 잡힌다 — 분량이 네 배 많고 쟁점을 명시적으로 열거하기
때문이다. 채점기준표는 배점 항목 위주라 덜 나오지만, 없던 120회차를 메웠다.

쟁점이 하나도 안 붙은 6회차는 **원본이 짧거나 없는 경우**다.

| 회차 | 채점기준표 | 해설 |
|---|--:|--:|
| 공법 2014-3차 | 56자 | 없음 |
| 공법 2017-2차 | 455자 | 없음 |
| 공법 2017-3차 | 796자 | 없음 |
| 공법 2018-2차 | 1,348자 | 없음 |
| 공법 2020-2차 | 1,419자 | 없음 |
| 형사법 변시 15회 | 없음 | 없음 |

각 쟁점이 어느 소스에서 왔는지는 `issueSource`에 남는다
(`{"PUB-0028": ["rubric"]}` 처럼).

### ID는 새로 만들지 않는다

쟁점 ID는 네 앱을 잇는 척추다(CASE_Practice `docs/ARCHITECTURE.md` 3절).
새로 지어내면 선택형·사례형과 연결이 끊긴다. 그래서 **사례형이 이미 발급한
레지스트리(PUB/CRI/CIV 1,454개)의 이름과 별칭을 해설에서 찾는** 방식으로 한다.

LLM을 쓰지 않는다. 결정론적이고, 비용이 없고, ID가 자동으로 정합한다.
레지스트리에 없는 쟁점은 잡히지 않는 것이 이 방식의 한계다 — ID 발급은
사례형 레지스트리(정본)를 건드리는 일이라 여기서 함부로 하지 않는다.

### 오탐을 줄인 두 가지

- **2자 키워드는 뺀다.** "배당"·"상계"·"자백"·"재심" 같은 말은 일반 문장에도
  흔해 아무 회차에나 붙는다(레지스트리 2,059개 키워드 중 7개).
- **해설에 2회 이상 나와야 인정한다.** 1회는 배경 언급일 수 있다.
- 긴 키워드를 먼저 본다 — "취소소송의원고적격"이 "원고적격"보다 구체적이다.
- 비교는 공백을 지우고 한다. 레지스트리는 "재판의전제성", 본문은 "재판의 전제성"이고
  OCR은 글자 사이에 공백을 더 끼워 넣는다.

### 검증

공법 15회에 붙은 쟁점은 표현의자유·명확성원칙·제소기간·과잉금지원칙·원고적격·
평등원칙·재량권의일탈남용이고, 같은 회차 해설의 핵심정리는 "표현의 자유에 대한
제한(과잉금지원칙, 명확성원칙), 행정소송의 요건(원고적격, 제소기간), 재량권의
한계(사실오인, 평등원칙, 비례원칙)"이다 — 그대로 맞다.

형사법 14회는 장물취득·범인도피죄가 잡혔고, 해설 목차의 공소사실이
"장물취득의 점, 범인도피의 점"이다.

## AI 자동채점

사례형과 **같은 워커**([CASE_Practice `worker/`](https://github.com/evenoa9218-gif/CASE_Practice/tree/main/worker))를
쓴다 — 시험 ID 꼬리(`_사례`/`_기록`)로 데이터 저장소와 채점 프롬프트가 갈린다.

기록형 채점위원 프롬프트는 사례형과 다른 것을 본다.

- **서면 양식** — 서면 종류별 필수 기재사항(소장의 청구취지·청구원인,
  헌법소원심판청구서의 적법요건, 변론요지서의 증거 탄핵 구조 등)
- **청구취지·주문 문구** — 금액·이자 기산일·목적물 표시를 글자 단위로.
  틀리면 올바른 문구를 그대로 제시한다
- **기록 인용의 정확성** — 기록에 없는 사실을 지어냈으면 명시적으로 지적

스모크 검증: 기록과 무관한 보일러플레이트 답안에 3/100점을 주며 "당사자
표시 전면 오류(기록의 이원교 ≠ 답안의 홍길동)", "제68조 제2항 사건에
제1항 양식 사용"을 정확히 짚었다 — 기록 대조가 실제로 작동한다.

채점 근거는 기준표(모의 120) → 해설(변시 44) 순으로 쓰고, 서면 탭마다 따로
채점된다. 피드백 전문은 이 기기에만 남는다.
