# 기록형 연습 — 변호사시험

변호사시험 기록형 기출·모의고사를 실제 시험처럼 풀고, 답안을 기기에 남기는 앱.
허브(`evenoa9218-gif.github.io`) 아래 네 번째 위성 앱이다.

공유 규약(오리진·저장 계층·쟁점 ID·화면 토큰)은
[CASE_Practice의 `docs/ARCHITECTURE.md`](https://github.com/evenoa9218-gif/CASE_Practice/blob/main/docs/ARCHITECTURE.md)가 정본이다.

## 담긴 것

과목별 **55회차**(변호사시험 15 + 법전협 모의고사 40), 3과목 165회차.

| 과목 | 회차 | 채점기준표 |
|---|--:|--:|
| 공법 | 55 | 40 |
| 민사법 | 55 | 40 |
| 형사법 | 55 | 40 |

**변호사시험 15회분은 채점기준표가 공개되지 않는다** — 모의고사 40건에만 있다.
사례형과 같은 상황이고, 목록에서 회차마다 표시된다.

## 화면

- **좌우 2단** — 왼쪽 기록, 오른쪽 서면 작성. 각각 따로 스크롤한다. 기록형은
  기록이 1만~9만 자라 위아래로 쌓으면 쓰면서 보기가 불가능하다. 900px 미만에서는 1단.
- **서면별 탭** — 한 회차에 검토보고서·변론요지서처럼 서면이 둘이면 탭으로 나뉘고
  답안도 따로 저장된다.
- **임시저장** — 입력이 멎고 0.6초 뒤 자동 저장. 서면 단위(`{시험ID}::t{번호}`).

답안 전문은 **이 기기에만** 남는다(IndexedDB). 원격에는 점수·시간 같은 요약만 간다.

## 데이터 만들기

원본 hwp/txt는 저작권 자료라 저장소에 없다. 경로를 환경변수로 주고 돌린다.

```bash
set RECORD_RAW=C:\...\모의고사 기출문제, 모범답안
cd pipeline
python -X utf8 build_record_data.py
```

`data/{과목}/index.json` + `exams/*.json`을 다시 만든다.

### 작성할 서면을 어떻게 찾는가

과제 표기가 과목마다 근본적으로 다르다.

| 과목 | 표기 | 예 |
|---|---|---|
| 공법 | 로마자 번호 + 배점 | `Ⅰ. 헌법소원심판청구서의 작성 (50점)` |
| 형사법 | 문장 안, 번호·배점 없음 | "…검토보고서를, …변론요지서를 각 작성하되" |
| 민사법 | 과제 하나, 번호·배점 없음 | "…소장을 작성하시오." |

번호나 배점으로 찾으면 공법만 잡히고 나머지는 전부 실패한다. 그래서 번호가 아니라
**작성할 서면 종류**(소장·답변서·변론요지서·검토보고서·헌법소원심판청구서 등)를
기준으로 찾는다. 배점은 서면 이름 뒤에 붙어 있으면 같이 읽고, 없으면 비워 둔다.

각 회차의 `taskSource`가 무엇을 보고 뽑았는지 남긴다.

| `taskSource` | 뜻 | 건수 |
|---|---|--:|
| `points` | 배점까지 찾음 | 36 |
| `document` | 서면 종류만 찾음(배점 없음) | 124 |
| `none` | 못 찾음 — 답안칸 하나로 폴백 | 5 |

`none` 5건(공법 2014-3차·2015-1차, 민사법 변시 3회, 형사법 2014-3차·2016-2차)은
문제 표지 형식이 달라 자동으로 못 뽑았다. 앱은 답안칸 하나를 주고 "기록에서
확인하세요"라고 알린다 — **틀린 과제 목록을 지어내지 않는 쪽**을 택했다.

## 채점 근거 — 해설서 결합

변시 15회분은 채점기준표가 공개되지 않는다. 그 공백을 **기록형 해설서**로 메웠다.

| 과목 | 회차 | 채점기준표 | 해설 | 근거 있음 |
|---|--:|--:|--:|--:|
| 공법 | 55 | 40 | 15 | 55 |
| 민사법 | 55 | 40 | 15 | 55 |
| 형사법 | 55 | 40 | 14 | 54 |
| **합계** | **165** | **120** | **44** | **164** |

근거가 없는 건 형사법 변시 15회 한 건뿐이다(가장 최근 회차라 해설서가 아직 없다).

### 쓴 책과 판정

| 책 | 쪽수 | 회차 머리글 | 결과 |
|---|--:|--:|---|
| 김유향 공기록 해설(공법) | 364 | 44% | 15회차 결합 |
| 노수환 핵심형사기록(형사법) | 819 | 48% | 14회차 결합 |
| 정연석 로스쿨 기록형 기출문제집(3과목) | 1,032 | 45% | 15회차 결합 |
| 정연석 15변시 기록형 해설 | 21 | 100% | 1회차 결합 |
| 김기용 COMPACT 형사기록 | 396 | 17% | **회차 매칭 안 함** |

김기용 책은 창작 기록 위주라 회차별로 나뉘지 않는다. 무리하게 붙이면 엉뚱한
해설이 달리므로 제외했다 — 쟁점 태깅용 참고자료로는 여전히 쓸 수 있다.

### 어떻게 회차를 찾는가

사례집 목차를 파싱하는 사례형 방식은 여기서 통하지 않았다. 다섯 권의 편집이
제각각이고, 김유향 책은 OCR본이라 목차 자체가 깨져 있다("재 2 편", "71 줄문제집").

대신 **쪽마다 반복되는 회차 머리글**("2023년 제12회 변호사시험")로 나눈다.
OCR이 글자를 흘려도 숫자와 '회/년'은 대체로 살아남는다. 머리글이 없는 쪽은
직전 회차를 물려받는다.

### 붙인 뒤 반드시 대조한다

머리글이 잡혔다고 내용까지 맞다는 보장은 없다. 그래서 **문제에만 나오는
고유명사**(기록형은 당사자 이름이 회차마다 다르다)를 뽑아 해설에 실제로
등장하는지 센다. 적중률 50% 미만은 붙이지 않는다.

이 대조로 실제 오매칭을 걸러냈다. 공법 2016-2차에 붙었던 11쪽은 적중률이
25%였는데, 열어 보니 문제는 건축·용도변경허가 사건인데 해설은 재외동포법·
환경영향평가법이었다 — 회차별 해설이 아니라 유형별 청구취지 예시를 모아 둔
정리 페이지가 회차 하나로 잡힌 것이었다. 쪽수만으로는 걸러지지 않았다.

최종 결합 45건은 전부 적중률 0.5 이상이다.

### 재생성

```bash
set RECORD_PDF=C:\...\모의고사 기출문제, 모범답안
cd pipeline
python -X utf8 extract_casebooks.py   # PDF → 쪽별 txt (2,632쪽, 20분쯤)
python -X utf8 split_casebooks.py     # 회차별 블록으로 묶기
python -X utf8 verify_match.py        # 내용 교차검증
python -X utf8 merge_casebook.py      # 검증 통과분만 data/에 결합 + OCR 정제
```

`work/`는 중간 산출물이라 커밋하지 않는다. 원본 PDF도 저작권 자료라 저장소에 없다.
